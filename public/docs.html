WorkoutQuest API

A GraphQL API for tracking workouts and player progress. Everyone can read data. Signed-in players can create, change, and delete their own data. Every request goes to one endpoint.

Quick start

Send a POST to /graphql with a JSON body containing query and, optionally, variables. Reads need no sign-in:

curl -X POST "$BASE_URL/graphql" \
  -H "content-type: application/json" \
  -d '{"query":"{ workouts { id name type xpReward } }"}'
ItemValue
EndpointPOST /graphql (also serves an interactive explorer on GET in a browser)
Content typeapplication/json

Authentication

Sign-in uses GitHub OAuth and a server-side session cookie. All mutations require it; queries do not.

RoutePurpose
GET /auth/githubStart sign-in. Redirects to GitHub. Returns 503 with a missingVariables list if OAuth is not configured on the server.
GET /auth/github/callbackGitHub redirects back here. Creates the player on first sign-in, starts the session, and redirects to /.
GET /auth/meReturns the signed-in player, or 401.
POST /auth/logoutEnds the session.

To call mutations from a browser, sign in at /auth/github on the same origin, then use the console below or the app. From scripts, reuse the workoutquest.sid cookie from a signed-in browser.

Ownership rules: you can change or delete only your own workouts. You can change or delete a player profile only if it is yours or you created it. Completing a workout awards its XP to you once; level is floor(totalXp / 500) + 1. A player's email is returned only to that player.

Errors

Failures come back in the standard GraphQL errors array. Branch on extensions.code, not on the message text.

CodeMeaning
BAD_USER_INPUTValidation failed or an id is malformed. extensions.errors lists each failing field and message.
UNAUTHENTICATEDThe operation needs a signed-in player.
FORBIDDENThe record exists but belongs to someone else.
NOT_FOUNDNo record with that id.
CONFLICTDuplicate username or email, or the workout is already completed.
INTERNAL_SERVER_ERRORUnexpected failure. Details are logged on the server, never returned.
{
  "errors": [{
    "message": "Validation failed",
    "extensions": {
      "code": "BAD_USER_INPUT",
      "errors": [{ "field": "difficulty", "message": "difficulty must be 1-10" }]
    }
  }]
}

Validation rules

FieldRule
Workout nameRequired, trimmed, up to 100 characters
difficultyWhole number, 1 to 10
durationMinutesWhole number, 1 to 300
xpRewardWhole number, 0 to 10000
exercisesUp to 50. Each needs a name (up to 80 characters), sets (1 to 100), and reps (1 to 1000)
Player username3 to 30 characters: letters, numbers, _, -
displayNameRequired, up to 60 characters
emailValid email, stored lowercase
avatarUrlOptional, must be a URL

Examples

The four REST verbs map to GraphQL like this: GET is a query, POST is a create… mutation, PUT is an update… mutation (replaces all fields), and DELETE is a delete… mutation.

Read (GET)

query {
  workouts(type: STRENGTH, completed: false) {
    id name difficulty durationMinutes xpReward
    exercises { name sets reps }
    player { username }
  }
}

Create (POST)

mutation {
  createWorkout(input: {
    name: "Leg Day", type: STRENGTH, difficulty: 7,
    durationMinutes: 50, xpReward: 220,
    exercises: [{ name: "Squats", sets: 4, reps: 10 }]
  }) { id name }
}

Replace (PUT)

mutation {
  updateWorkout(id: "WORKOUT_ID", input: {
    name: "Leg Day", type: STRENGTH, difficulty: 8,
    durationMinutes: 55, xpReward: 250
  }) { id difficulty }
}

Complete and earn XP

mutation { completeWorkout(id: "WORKOUT_ID") { id completed completedAt } }

Delete (DELETE)

mutation { deleteWorkout(id: "WORKOUT_ID") { id deleted } }
